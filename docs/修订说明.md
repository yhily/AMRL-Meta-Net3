## 修改理由与位置

|问题|修改|理由|
|---|---|---|
|原 PPO 没有 clipped PPO/rollout|`rl/` 改用 SB3，`experiments/engine.py` 统一训练|避免算法名称与实际计算不一致|
|元控制器未优化|`amrl/meta_ppo.py`、`meta_learner.py`、`experiments/engine.py`|增加带价值函数的 recurrent PPO、GAE、正确的 tanh log-prob，并记录参数变化|
|HPController 输出未应用|`hyperparameter_controller.py` 的 `apply`|更新实际 optimizer、gamma、rollout buffer 和 epsilon/entropy coefficient|
|更新公式与论文不一致|采用 `alpha*(1+delta)`、gamma 上界 .999、双重 learning-rate 投影|与论文对应公式一致；所有消融条件仍可追踪|
|评估未训练模型|`evaluate.py` 强制指定 checkpoint|评价已训练模型，保留独立评估种子和逐 episode 分数|
|旧 Gym / dm_env 混用|`envs/make_env.py`|适配 Gymnasium，明确 bsuite 实例 ID 与随机种子|
|仅汇总均值，缺 seed 原始数据|`experiments/run.py` 和 `summarize.py`|每个训练 seed 单独建档，完整性检查后再配对统计|
|消融不完整|主脚本生成 MLP、feature mask、interval、bound 和 no-drift 变体|分别重新训练控制器，在统一内层交互预算下比较|
|跨算法无专用或联合控制器|PPO pooled、A2C/DQN-specific、joint 四类|对照冻结 PPO 控制器与专用/联合训练，并保存训练来源|
|跨任务混同 pooled transfer|独立 source-only 和 target-trained 控制器|三组有向迁移使用真实源任务训练，不偷用目标元训练数据|
|元训练成本漏内层|`controllers/*/cost.json`|同时记录内层 rollouts、基础学习器更新、外层 PPO、检查点和完整总时间|
|复用成本重复计算|`cost_summary.json`|对每个训练控制器、TPE study 只计一次；first-use 另计源/目标所需唯一初始化成本|
|旧入口与 notebook 不能运行|重写入口、shell 示例、合法 notebook JSON|同一套命令可在本机或 Colab 使用；不再宣传旧版“一键复现论文”|

## 与当前论文仍需协调的事实

- 数据预算：pilot 每次内层/部署训练 1024 步，正式配置为 100k 步。pilot 只能证明全流程可运行，不能作为完整强度的审稿补实验。
- 元训练规模：pilot 每控制器 9 个完整内层 episode；正式配置 36 个。这是本次公开设定，不是从历史日志恢复的原始数目。
- bsuite：当前明确运行 `memory_len/0` 和 `catch/0`，输出 raw episode return。不能将这些结果改写成论文现有 0–1 normalized score、capability radar 或完整 bsuite 泛化结果。
- TPE：固定预算、真正训练候选，并采用独立调参 seed；未使用 median pruning。论文如采用新结果，需同步这一差异。
- 诊断：梯度范数是在优化器 step 前、但 SB3 裁剪后测得；loss 为最后一次训练更新的汇总量，梯度窗口为 interval 粒度。这不是已核实的历史诊断实现。
- 算法：新基础学习器是 SB3 2.7.1；网络为两个 64 单元隐藏层。不能声称与旧论文所有未公开训练设置完全相同。
- PBT：本轮没有实现或重跑 PBT，因此不更新原 PBT 对照或对应优越性声明。
- 完整元训练成本：输出是本机 CPU 上新实验的真实计时，不是旧论文 T4 的历史耗时，也不代表原 0.8%–1.2% 在线开销得到复核。

## 正式实验规模与状态

运行正式实验时，可从仓库根目录使用 README 中的命令；中断后重新使用完全相同的配置和输出路径。已完成的 controller / job 会跳过，部分完成的 controller 会重跑。不要在同一个输出目录中混用不同代码版本或修改训练预算。
